# Yoko geri v3: сигнатура удара — быстрый и медленный пути

**Дата:** 2026-08-08
**Статус:** одобрено к реализации (дизайн)
**Дополняет:** `2026-08-06-yokogeri-apex-gate-design.md` (заменяет его гейт)
**Тема:** после гейта верхушки гэдан всё ещё засчитывает подъёмы колена и махи.

## Улики

Сессия 01:53 (граунд-трус: чередование ударов и не-ударов), 14 взмахов, код с
телефона даёт 9/5. Двухслойная причина:

1. **Лаг сглаживания.** Гейт сравнивал с `_smoothedLift`, который отстаёт от
   сырого сигнала: после высокого замаха первые кадры опускания ещё держат
   sm ≥ 1.0, хотя нога реально на 0.75 и уже распрямилась маятником — опускания
   просачивались сквозь гейт.
2. **По высоте удар и опускание неразделимы.** Настоящие медленные гэданы из
   размеченной сессии 07:41 выпрямляются на сыром подъёме 0.46–0.95 (стопа у
   колена опорной — гэдан и есть удар этого уровня), опускания проходят те же
   высоты. Разделяет их **время**: удар держит прямую ногу в рабочей полосе
   2–6 кадров (контроль), опускание проносится за ≤ 1 кадр (гравитация;
   максимум наблюдённого выпрямления на опускании — 0.99, единичный кадр).

## Правило зоны (v3)

Кадр учитывается только выпрямленным (2D-колено ≥ 150°, как раньше). Гейт — по
**сырому** подъёму текущего кадра (`lift` бьющей ноги до сглаживания);
сглаживание остаётся только в фазах `LegLiftCycle`.

- **Быстрый путь:** кадр с сырым подъёмом ≥ **1.2** (fastKickAt) даёт зону сразу
  — быстрые чудан/дзёдан живут одним кадром, а опускания выше 0.99 не
  выпрямляются (запас 20 %).
- **Медленный путь:** кадры с сырым подъёмом ≥ **0.45** (kickBandAt) дают зону,
  только если таких кадров за цикл ≥ **2** (minBandFrames) — сигнатура
  контролируемого удара, отсекающая мимолётное выпрямление опускания.
- Пик цикла = максимум зон быстрого пути и (при выполнении порога кадров)
  медленного. Дальше как раньше: пик ≥ заданной зоны → Reps++, ниже → «Выше»,
  пусто → «Выпрями ногу»; `BestZone`, `TotalLiftedSeconds` без изменений.
- Свойство `LegLiftCycle.LiftedAt` (добавлено прошлым фиксом) больше никем не
  используется — удалить.

Проверка правила на всех записях: 07:41 (размечена) → **4/3/Chudan** — ровно
граунд-трус и ровно текущие корпусные ассерты; 01:53 → **7/7/Chudan** —
согласуется с «чередовал»; приседания 03:05 → 0/0; ходьба → **0 зачётов**
(5 no-rep'ов от шагов — допустимо, фантомных повторов нет).

Пороги 1.2 / 0.45 / 2 — из измерений; не «улучшать» без новых записей.
Оговорка: minBandFrames = 2 привязан к ~15 fps пайплайна устройства (0.13 с
выпрямления); при смене fps пересмотреть.

## Тесты

- Существующие тесты yoko переживают без правок ассертов: одиночные зонные
  кадры билдера имеют сырой подъём ≥ 1.25 → быстрый путь; тест опускания
  (`ExtensionOnlyOnDescentDoesNotAward`, кадр на 0.6) — одиночный кадр полосы,
  отвергается; замах согнутым коленом — как был.
- Новый юнит-тест `SlowLowKickCountsThroughBand`: Floor → `ChamberHigh` (вход в
  цикл, колено согнуто) → два кадра `Kick(0.78)` (прямая нога, подъём 0.6 —
  полоса) → Floor: Reps 1, NoReps 0 — медленный низкий удар считается. На
  текущем коде красный (sm-гейт режет полосу: 0 повторов).
- Корпуса: `yoko_gedan_session.csv` (07:41) — ассерты **не меняются**
  (4/3/Chudan; красная фаза не ожидается — правило совпадает с текущими
  числами); новый `yoko_gedan_mixed.csv` (= `pose_rec_015348.csv`) →
  **Reps 7, NoReps 7, BestZone Chudan** (на текущем коде — 9/5, красная фаза);
  `walking_noise.csv` через `YokoGeriAnalyzer(Gedan)` → **Reps 0**.
  Корпусы пуш-апа (5/4/0), приседа (18/15/1), wall-sit (6/0) не трогаются.

## Верификация

EditMode зелёные → `unity build` → `adb install` → живая проверка: гэдан-удары
(медленные и быстрые) считаются; подъёмы колена, махи без выпрямления и просто
опускание ноги — нет.
