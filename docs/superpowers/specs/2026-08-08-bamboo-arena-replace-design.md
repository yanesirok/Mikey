# Замена арены боя на BambooArena (сцена из архива)

**Дата:** 2026-08-08
**Ветка:** frontend/scene-architecture-hybrid
**Статус:** одобрено

## Задача

Прислали готовую сцену арены — `Assets/Fight/NewArena/BambooArena_scene.zip` (бамбуковая
роща с мостом через канал, собрана и оптимизирована под фиксированную камеру, подробности в
HANDOFF.md внутри архива). Нужно полностью заменить ею текущую арену боя.

## Контекст (что выяснено)

- Текущая арена в `FightSandbox.unity` — префаб-инстанс `BambooGrove.glb`
  (GUID `e1b7c2eb…`); его файлы в `Assets/Fight/NewArena/` уже удалены с диска,
  удаления не закоммичены. Сцена сейчас со сломанными ссылками.
- Архив — самодостаточный пакет: `Assets/BambooArena/**` (GLB 42 МБ, 13 оптимизированных
  мешей-.asset, материалы, текстуры, `RiverWater.shader`, `PlanarReflection.cs`),
  сцена `Assets/Scenes/SampleScene.unity`, `Assets/Settings/**`, часть `ProjectSettings/**`.
  Все .meta на месте — GUID сохраняются, сцена подвязывается сама.
- **Коллизии GUID:** оба проекта из одного URP-шаблона. Архивные `SampleScene.unity`,
  `Settings/*` несут те же GUID, что наши. Наш `SampleScene.unity` — персистентная
  App-сцена с UI (единственная в билде). Слепая распаковка уничтожила бы её и наши
  игровые настройки рендера.
- **Версии Unity:** проект 6000.3.18f1, архив собран в 6000.5.7f1 (новее). Решение:
  пробуем импорт как есть; если меши/сцена побьются — отдельно решаем про апгрейд.
- Вода самодостаточна: отражение через `_ReflectionTex`, который ставит
  `PlanarReflection.cs`; opaque texture и depth priming из их настроек не обязательны
  (priming — только оптимизация).
- Волюм-профиль их сцены указывает на GUID нашего `SampleSceneProfile.asset`, но контент
  другой (exposure 1.35 и т.д.) — профиль надо разводить.
- Слои совпали: их layer 8 «Reflect» = наш layer 8 «Reflected». Ничего не меняем.
- Из старой рукодельной арены `Assets/Fight/Arena/**` снаружи используются только
  `Character.shader` (материалы тел бойцов) и `M_BlobShadow.mat` (FightSandbox).
  Шейдер блоб-тени лежит не в этой папке — удалению не мешает.

## Решение

Сцена арены **становится** FightSandbox: геймплей переезжает в неё, а не арена в старую
сцену. Так туман, свет, волюм и все префаб-оверрайды мешей приезжают нетронутыми —
сценовые настройки (RenderSettings) при пересадке объектов руками не переезжают, поэтому
обратное направление отброшено. Аддитивная загрузка для дев-песочницы отброшена как
лишняя механика (RenderSettings принадлежат активной сцене, в редакторе пришлось бы
держать две сцены).

### 1. Импорт из архива

- Распаковать в проект: `Assets/BambooArena/**` (со всеми .meta), `HANDOFF.md` →
  `Assets/BambooArena/HANDOFF.md`.
- Содержимое их `Assets/Scenes/SampleScene.unity` записать **поверх**
  `Assets/Scenes/FightSandbox.unity`. Наш `FightSandbox.unity.meta` остаётся — GUID
  сцены не меняется. Наша App-сцена `SampleScene.unity` не затрагивается.
- Их `Assets/Settings/SampleSceneProfile.asset` извлечь как **новый ассет**
  `Assets/BambooArena/BambooArenaProfile.asset` (новый GUID) и перевязать Global Volume
  перенесённой сцены на него.
- **Не брать:** их `Assets/Settings/**` (кроме профиля выше, под новым GUID),
  `ProjectSettings/**`, `SampleScene.unity.meta`. Наши RP-ассеты, качество и графика
  остаются как есть.
- Гейт: лог импорта unity-cli без ошибок по 13 мешам-.asset и сцене. Ошибки →
  стоп, вопрос апгрейда до 6000.5.

### 2. Сборка сцены

- Из старого FightSandbox перенести только геймплей: бойцы (с их блоб-тенями),
  `TouchControls`, `FightRound`. Старые Main Camera, Directional Light, FillLight,
  PostProcessing — не переносить (у арены свои: камера по handoff, Key Sun + Fill Light,
  Global Volume).
- Все корни арены **вместе с их камерой и светом** сгруппировать под пустышку
  `ArenaRig`, повернуть на 180° по Y и сдвинуть так, чтобы верх палубы моста лёг на
  y=0, а центр пролёта моста — под серединой отрезка между бойцами (высота палубы и
  центр измеряются по bounds моста в редакторе). Камера и свет
  едут тем же преобразованием: композиция кадра, направление света и гарантии
  culling-видимости (просчитаны под эту камеру, диапазон x ±6) сохраняются. Бойцы
  остаются на своих координатах лицом к камере — геймплей-код и спавны не трогаем.
- На камеру арены добавить `AudioListener` (если нет). Проверить, что culling mask
  `PlanarReflection` соответствует нашему слою 8.
- Сохранить как `FightSandbox.unity`.

### 3. Чистка

- `Assets/Fight/NewArena/**` — докоммитить удаления; сам zip (+ его .meta) удалить
  после распаковки.
- `Assets/Fight/Arena/**` удалить целиком, кроме `Character.shader` и
  `M_BlobShadow.mat` — их переместить в `Assets/Fight/character/` вместе с .meta
  (GUID сохраняются, ссылки не рвутся).
- Удалить Editor-генераторы старой арены: `BambooArena.cs`, `ArenaRefImporter.cs`,
  `ArenaTextures.cs`, `WaterProbe.cs`. `FightCapture.cs` остаётся.

### 4. Проверка

1. Лог импорта без ошибок (гейт из секции 1).
2. Скриншот Game view с камеры арены — сверка композиции с handoff: мост, роща,
   вода с отражением, туман.
3. Плей песочницы: бойцы стоят на палубе, управление и FightRound работают.

## Ограничения из handoff (наследуем)

- Камера двигается латерально только в x ±6 относительно арены — шире появятся дыры
  в листве (видимость резалась по 13 позициям камеры).
- `RiverWater.shader` обязан сохранять пассы `DepthOnly`/`DepthNormals`, если когда-то
  включим depth priming.
- Планарное отражение — самая дорогая часть кадра (сцена рисуется второй раз,
  scale 0.385); первый кандидат на срез, если девайс не тянет.
- Depth priming на Mobile-пути не проверялся автором — не включать без замера.
