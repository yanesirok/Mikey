# Новая арена: бамбуковая роща из Blender

**Дата:** 2026-08-05
**Статус:** дизайн согласован

Заменяет процедурную арену (`BambooArena.cs` и специи 07.11–08.02) готовой сценой из Blender.
Источник: `Assets/Fight/NewArena/UNITY_HANDOFF (2).md` — руководство переноса; цифры ниже
берутся оттуда и здесь не переспориваются.

## Решения, принятые на брейншторме

- **Камера — из handoff, фиксированная.** Сцена вырезана фрустумом под неё; боевая
  `FightCamera` (слежение + зум 5.2–8.5) со сцены снимается, код остаётся. Доводка кадра —
  отдельной итерацией, пользователь это явно разрешил («поставь, остальное исправим после»).
- **Путь переноса — GLB + editor-скрипт**, не прямой импорт .blend и не ручная сборка.
- Старая арена (`Assets/Fight/Arena/`, `BambooArena.cs`) с диска **не удаляется** — только
  уходит из сцены. Чистка — отдельной задачей, когда новая арена приживётся.

## 1. Пайплайн ассетов

Сейчас в `Assets/Fight/NewArena/` лежат `bamboo_grove.blend` (190 МБ) и `unity.zip` — Unity
с установленным Blender попытается импортировать .blend целиком, а 190 МБ не место ни в
Assets, ни в git.

- `bamboo_grove.blend` → `tools/Blender/bamboo_grove.blend`, строка в `.gitignore`.
- `unity.zip` удаляется; пять запечённых альбедо из него уже распакованы — переезжают в
  `Assets/Fight/NewArena/Textures/` (bamboo_bark, bamboo_leaf, fern, ground, rock).
- `UNITY_HANDOFF (2).md` остаётся рядом как документация.

Новый скрипт `tools/Blender/export_arena_glb.py` (запуск headless:
`blender.exe -b bamboo_grove.blend -P export_arena_glb.py`, Blender 5.1 стоит в
`C:\Program Files\Blender Foundation\Blender 5.1`):

- удаляет `FogDomain` (Cycles-объём, в Unity был бы 130-метровым кубом);
- `Backdrop` **экспортирует** — камера фиксированная, для неё плоский задник корректен;
- glTF 2.0 → `Assets/Fight/NewArena/BambooGrove.glb`: +Y Up, меши/UV/нормали/материалы,
  vertex colors включены (пригодятся для ветра), компрессия выключена.

GLB коммитится в git (порядка 10–20 МБ — терпимо, это теперь исходник арены для Unity).

## 2. Импорт в Unity

Unity не читает glTF из коробки. В `Packages/manifest.json` добавляется официальный
`com.unity.cloud.gltfast` — редакторский ScriptedImporter, .glb становится обычным ассетом.
Единственная новая зависимость дизайна.

## 3. Материалы

Строго по таблице handoff, все на URP/Lit с запечёнными альбедо (кроме воды):

| материал | Surface | почему |
|---|---|---|
| fern_02 | **Opaque** | листья — геометрия, альфа 99.8% непрозрачна; clip сломал бы early-Z на 36% треугольников сцены |
| M_ArenaLeafCard | Alpha **Clip**, cutoff 0.35 | blend не пишет глубину — ломает сортировку карт и теневой проход |
| M_ArenaBamboo, Bank, boulder_01, weathered_planks | Opaque | |
| Water | существующие `Water.shader` + `WaterReflection.cs` | это «better»-вариант из handoff (планарное отражение), уже написан и отлажен под тот же скользящий ракурс |

Нормали и roughness приезжают в GLB как есть. Мох на камнях (Shader Graph по мировой
нормали) — **не делаем**: handoff сам помечает его опциональным, камни уже затемнены запёкой.

## 4. Сцена

Одноразовый идемпотентный editor-скрипт `Assets/Editor/NewArenaScene.cs` (пункт меню, в духе
`BambooArena.cs`) пересобирает окружение в `FightSandbox.unity`:

- удаляет старый корень `Arena`, ставит `BambooGrove.glb` новым корнем `Arena`;
- назначает материалы из §3 (gltfast создаст свои — заменяем на наши ассеты, чтобы настройки
  жили в файлах, а не в импортере);
- **свет**: key — directional X 40° Y 52°, интенсивность ~3.0, тёплый (1.0, 0.78, 0.52),
  с тенями; fill — X 18° Y −208°, ~0.4, холодный (0.82, 0.87, 1.0), без теней;
  ambient — низкий тёплый, не чёрный (ориентир handoff: key к ambient ≈ 20:1);
- **туман**: экспоненциальный, плотность 0.0125, цвет — тёплый бледно-кремовый горизонта
  (сверяем по референс-рендеру из §6: 10 м → 12%, 25 м → 27%, 45 м → 43%);
- **камера**: позиция (−0.68, 2.60, −3.219) + дельта выравнивания из §5, поворот X 5°,
  Y 0.5°, FOV 45.7 (вертикальный), клипы 0.05/500; компонент `FightCamera` снимается;
- **пост**: Volume с Depth of Field (Bokeh, фокус 6.18, апертура 2.8).

## 5. Интеграция боя — минимум

- Арена ставится с одним смещением-константой: верх настила моста → y = 0 (пол бойцов),
  середина пролёта → x = 0, линия боя на настиле → z = 0. Камера сдвигается той же дельтой,
  композиция кадра не меняется. Конкретное значение дельты снимается с геометрии GLB при
  реализации.
- Бойцы, `FightRules` (ArenaHalfWidth = 3, пол y = 0) — не трогаем.
- Мосту — BoxCollider по настилу и дочерний объект `Timber` под корнем `Arena`: диагностика
  `FightBootstrap` ищет `Arena/Timber` рейкастом.
- Пан камеры не нужен: при FOV 45.7 кадр на глубине моста (~6 м) покрывает ±4.6 м по
  горизонтали, бойцы ходят в ±3. Статичная камера видит весь бой с запасом.

## 6. Проверка

- Референс-кадр: `renders/full.png` из handoff в репо нет — рендерим сами из .blend тем же
  headless-Blender (один кадр, 128 сэмплов Cycles — хватает для сравнения на глаз), кладём в
  `docs/superpowers/specs/refs/2026-08-05-bamboo-grove-ref.png`.
- Скриншот сцены существующим `FightCapture` — сравнение с референсом на глаз: композиция,
  туман, свет, отражение в воде.
- Прогон боя в `FightSandbox`: бойцы стоят на настиле (не тонут, не парят), бой играется,
  диагностика деки в консоли не ругается.
- Editor-скрипт идемпотентен: повторный запуск не плодит дублей света/волюмов.

## Вне скоупа первой фазы

Мох на камнях, световые лучи (handoff: делать пост-процессом, если захочется), пан/зум
камеры за бойцами, удаление старой арены и её шейдеров, мобильная оптимизация (185k
треугольников и 9 draw calls уже в бюджете; главный риск — overdraw альфа-теста — закрыт
ферном-Opaque и клипом на листьях).

## Известные риски

- **Параллакс задника** при любом будущем движении камеры — handoff §6; решение отложено
  вместе с решением о пане. Если камера останется строго статичной, задник корректен.
- **Blender 5.1 против версии .blend** — файл собран у автора handoff; если 5.1 его не
  откроет или glTF-экспорт разложится, ставим ту версию Blender, в которой файл собран
  (видно в заголовке .blend).
- **Масштаб/оси GLB в gltfast** — сверяем габарит моста (~пролёт из handoff) сразу после
  импорта, до сборки сцены.
