# Пуш-ап: щедрый зачёт уровня 0 — дебаунс вместо сглаживания

**Дата:** 2026-08-04
**Статус:** одобрено к реализации (дизайн)
**Дополняет:** `2026-08-04-pushup-evidence-gates-design.md`
**Тема:** после гейтов по уликам настоящие отжимания теряются (счёт 3 из 5–6), а
удержание планки иногда даёт фантомный повтор. Философия уровня 0 подтверждена
пользователем: **проверяем навык и выносливость, не учим** — считать всё, что в
основе отжимание, даже с ошибками формы; не считать позы без движения.

## Улики (запись 20:59, граунд-трус пользователя: 5–6 отжиманий + удержания планки)

- Отгруженная логика: 3 повтора из 5–6. Реплей-сетка по трём записям нашла воров:
- **EMA-сглаживание (α=0.6)** на реальном fps (6–15 кадров/с с провалами) не успевает
  довести угол до порога низа — повторы тают. Без сглаживания запись даёт 5.
  Побочно: сброс EMA на каждом невалидном кадре делал «сглаженным» одиночный сырой
  кадр — источник фантомов в планке.
- **Гейт «тело прямое ≥135°»** заблокировал 252 кадра записи — провис таза в честном
  отжимании резал кадры середины повтора.
- Защиту от дрожания вместо EMA даёт **дебаунс**: фаза «низ» открывается только после
  2 подряд валидных кадров ниже порога — одиночный шумовой скачок в планке не
  открывает повтор.

Победившая конфигурация на трёх записях: свежая (правда 5–6) → **5**; ходьба
(правда 0) → **0**; старая «реальная» → 4.

## Фикс (правки дефолтов + один параметр)

1. **`RepCounter`**: новый параметр `downDebounceFrames = 1` — вход в Down только
   после N подряд вызовов `Update` со значением ≤ `downThresholdDeg` (сброс серии
   при значении выше порога). Дефолт 1 — поведение приседаний и существующих тестов
   не меняется. Пуш-ап передаёт 2.
2. **`PushUpAnalyzer`**: дефолт `smoothingAlpha` 0.6 → **1.0** (сглаживание
   выключено; параметр остаётся — тесты и будущая калибровка могут задать своё).
   Дефолтный счётчик — `new RepCounter(140f, 105f, 0.3, downDebounceFrames: 2)`.
3. **`PushUpFormEvaluator`**: дефолты `minVisibility` 0.6 → **0.5**,
   `positionMinDeg` 135 → **120** (огрехи формы — метка `NotStraight`/`NoReps`,
   а не блок счёта; совсем сломанные позы всё ещё режутся на 120).
4. Гейты «в кадре» и «ладони на полу» (реп-проверка запястья) — без изменений.

## Регрессионный корпус

- Новый файл `Assets/Pose/Tests/Recordings/pushups_with_plank_holds.csv`
  (= `pose_rec_205917.csv`) — **граунд-трус пользователя**: тест ожидает 5.
- `real_pushups.csv` — ожидание меняется 2 → **4** с комментарием: прежние «2» были
  не правдой, а находкой старой логики (пользователь тогда жаловался на потерю
  счёта); 4 — характеризационное значение новой конфигурации, защита от регрессий.
- `walking_noise.csv` — по-прежнему **0**.

## Верификация

EditMode-тесты (корпус 5/4/0 + все существующие) зелёные → `unity build` →
`adb install` → на телефоне: 5–6 честных отжиманий дают 5–6; удержание планки без
движения не двигает счёт; ходьба/жесты — не двигают.

## Вне области

- Дебаунс для приседаний/ударов — только если смоук покажет ту же проблему.
- Персональная калибровка порогов по игроку — после появления реальной статистики.
