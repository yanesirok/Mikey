# Уровень 0: CV-оценка техник и стартовые статы игрока

**Дата:** 2026-08-04
**Статус:** одобрено к реализации (дизайн)
**Тема:** шесть новых упражнений/техник поверх существующего pose-пайплайна + расчёт
стартовых статов игрока по итогам уровня 0. Мягкий скоринг: повтор засчитывается,
если основа движения правильная; огрехи формы фиксируются, но счёт не блокируют.

## Контекст

Пайплайн pose-детекции уже работает (спеки 2026-07-01 и 2026-07-03): нативный
MediaPipe-плагин (Android, LIVE_STREAM) → `PoseFrame` (normalized + world landmarks) →
`PushUpAnalyzer` → dev-песочница `ExerciseSandbox` с HUD, записью CSV и 3D-разборщиком
`PoseReviewer`. Точка расширения готова: `IExerciseAnalyzer` + `ExerciseCatalog` — новая
техника это одна запись в каталоге, контроллер/HUD/песочница её подхватывают сами.

Важно: политика подсчёта `PushUpAnalyzer` **уже мягкая** — полноамплитудный повтор
засчитывается всегда, огрех формы попадает в `NoReps`, но не блокирует счёт. Уровень 0
тиражирует этот паттерн, а не вводит новый режим.

## Границы (scope)

**В работе (эта спека):**

- 6 новых анализаторов: приседания, wall-sit hold, медленный yoko-geri,
  mae geri gedan / chudan / jodan (один класс, три записи каталога);
- общие примитивы: `RepCounter` (переименованный `PushUpRepCounter`), `HoldTimer`,
  `KickHeightZone`, `LegLiftCycle`;
- модель результатов `Level0Results` + `StatCalculator` → статы
  Сила / Выносливость / Гибкость / Баланс (0–100);
- проверка через существующую песочницу; EditMode-тесты; on-device smoke.

**Вне (отдельные спеки следом):**

- уровень 1: kizami zuki jodan (fudo dachi → zenkutsu dachi kamae) и mae geri chudan из
  стоек — требует распознавания стоек; фазовая структура анализаторов L0 — задел под это;
- игровой онбординг-экран оценки (последовательность из 7 упражнений → экран статов);
- «точный» режим обучения правильной технике (Strict-профили включаются там; вероятное
  направление скоринга — сравнение с эталоном по world-landmarks, задел: запись CSV и
  `PoseReviewer` уже есть);
- iOS.

## Решения по существу (итог обсуждения)

- «gedan, chudan, jodan» из ТЗ = **mae geri** (прямой удар ногой вперёд) на трёх высотах —
  три отдельные записи каталога.
- Статы: **Сила / Выносливость / Гибкость / Баланс**, шкала 0–100.
- Подход к анализаторам: **малые анализаторы на общих примитивах** (по образцу пуш-апа).
  Отклонены: декларативный конфиг-движок (преждевременное обобщение на 6 техник) и
  DTW-сравнение с эталоном (избыточно для мягкого L0; путь для «точного» режима).
- Флоу этой итерации живёт в dev-песочнице; игровой экран — следом.

## Архитектура

Всё в `Assets/Pose/` (asmdef `Mikey.Pose`), чистый C# без UnityEngine в логике —
EditMode-тестируемость, как у пуш-апа.

### Общие примитивы (ровно четыре)

1. **`RepCounter`** — существующий `PushUpRepCounter`, переименованный: чистый гистерезис
   по скалярному сигналу с двумя порогами и минимальным временем повтора. Ничего
   пуш-ап-специфичного в нём нет; пуш-ап продолжает им пользоваться, приседания и
   mae geri берут его со своими порогами и сигналами. Публичное поведение не меняется.
2. **`HoldTimer`** (новый, ~30 строк) — копит секунды, пока предикат «в позе» истинен;
   грейс-период ~1 с на кратковременную потерю трекинга (моргнувший трекер не обнуляет
   и не прерывает удержание). Для wall-sit.
3. **`KickHeightZone`** (новый, чистая функция) — классифицирует высоту лодыжки бьющей
   ноги по точкам **того же кадра**: ниже бедра = Gedan, между бедром и плечом = Chudan,
   на уровне плеча и выше = Jodan. Привязка к текущему кадру устойчива к перемещению
   игрока и не требует калибровки под рост.
4. **`LegLiftCycle`** (новый) — цикл подъёма ноги (пол → пик → пол), общий сигнал для
   mae geri и yoko-geri; отдельный от `RepCounter`, потому что не лёг на его семантику
   «верх/низ по одному порогу».

### Анализаторы

Каждый — маленький класс, реализует `IExerciseAnalyzer`, регистрируется в
`ExerciseCatalog`. Пороги — параметры конструктора с дефолтами (как 140°/105° у пуш-апа),
никаких конфиг-файлов.

**Профили Lenient/Strict:** анализаторы сразу принимают два набора порогов; в этой
итерации везде используется `Lenient` (мягкий: полная амплитуда = зачёт, форма → `NoReps`).
`Strict` — только параметры конструктора про запас (жёстче пороги, форма блокирует счёт);
нигде не включается, включит будущий режим обучения без переделки анализаторов.

Интерфейс `IExerciseAnalyzer` **не меняется**. Wall-sit отдаёт удержанные целые секунды
через `Reps`; в песочнице подпись «Wall-sit (сек)».

## Детекция техник

Ракурс — сбоку (профиль, как пуш-ап) у приседаний, wall-sit и mae geri; **лицом к камере**
у yoko-geri (нога уходит вбок — в профиль высоту не видно). Подсказка о ракурсе — текст
состояния Ready («Встань боком» / «Встань лицом»).

| Техника | Сигнал | Зачёт (Lenient) | В `NoReps` (не блокирует) |
|---|---|---|---|
| Приседания | угол колена (бедро–колено–лодыжка), EMA | `RepCounter`: стоя ≥ ~160° → низ ≤ ~100° → стоя = +1; недосед повтор не завершает (счёт просто не растёт, cue «Ниже») | сильный завал корпуса |
| Wall-sit | углы колена и бедра (плечо–бедро–колено) | `HoldTimer`: секунды, пока оба угла в окне ~70–120° | — (у удержания cue «Ниже»/«Выше» вместо no-rep) |
| Slow yoko-geri | высота лодыжки бьющей ноги | подъём вбок выше колена опорной **и** фаза подъёма ≥ ~2 с = +1; время в подъёме медленных циклов копится (`LegLiftCycle`) | быстрый мах (< 2 с) |
| Mae geri ×3 | высота лодыжки бьющей ноги + `KickHeightZone` | нога с пола → пик → возврат; +1 если пик в **запрошенной зоне или выше** (просили gedan, ударил chudan — зачёт) | пик ниже запрошенной зоны; нет сгиба колена перед выпрямлением (чамбер) — помечаем |

Общие правила:

- **Бьющая нога определяется автоматически** — та лодыжка, что поднялась; выбора
  «левая/правая» в UI нет.
- **Видимость**: у каждой техники свой обязательный набор точек (присед/wall-sit:
  бёдра + колени + лодыжки; удары: + плечо для зон). Ниже порога уверенности →
  `ExerciseFormState.NotVisible`, счёт/таймер на паузе — политика пуш-апа.
- **Anti-jitter**: EMA-сглаживание сигнала + минимальное время повтора
  (0.3 с; у mae geri ~0.2 с — удар быстрый).
- Все пороги стартовые; калибруются по CSV-записям через существующий пайплайн
  (`PoseController.RecordFrame` → `PoseReviewer`), как калибровался пуш-ап.

## Статы

Два чистых класса в `Mikey.Pose`:

- **`Level0Results`** — сырые итоги: повторы пуш-апов и приседаний, секунды wall-sit,
  медленные повторы + секунды удержания yoko-geri, максимальная достигнутая зона mae geri.
  Хранение: JSON (`JsonUtility`) в `PlayerPrefs` — самое простое, что переживает
  перезапуск; игровой профиль позже читает отсюда же.
- **`StatCalculator`** — маппинг в 4 стата, шкала 0–100, якоря — именованные константы
  (тюнятся по живым данным):
  - **Сила** = среднее из (пуш-апы: 30 повторов = 100) и (приседания: 40 = 100);
  - **Выносливость** = wall-sit: 120 с = 100;
  - **Гибкость** = максимальная зона mae geri: gedan = 33, chudan = 66, jodan = 100;
  - **Баланс** = yoko-geri: медленные повторы (10 = 70) + бонус за суммарное время
    в подъёме медленных циклов (20 с = +30).

Значения выше якоря обрезаются до 100. Все формулы линейные — сложнее не нужно, пока
нет статистики реальных игроков.

## Интеграция и поток данных

```
CameraX → MediaPipe (native) → PoseFrame
  → выбранный в песочнице IExerciseAnalyzer (6 новых записей каталога)
      → HUD песочницы: счёт/секунды, пилюля формы, cue   (без изменений устройства)
  → по завершении подхода: результат → Level0Results (PlayerPrefs)
      → StatCalculator → строка текущих статов внизу экрана песочницы
```

`ExerciseCatalog` получает 6 записей (`squat`, `wallsit`, `yokogeri-slow`,
`maegeri-gedan`, `maegeri-chudan`, `maegeri-jodan`). Песочница по устройству не
меняется; добавляется только запись результата завершённого подхода и строка статов.
Игровой онбординг-экран — следующая спека.

## Ошибки и деградация

Политика пуш-апа без изменений: тело не в кадре / низкая уверенность → `NotVisible`,
счёт и таймеры на паузе, подсказка кадрирования; отказ камеры → graceful-состояние;
пропуски точек → кратко держим состояние, повтор не засчитываем; у wall-sit грейс ~1 с.
Кадры обрабатываются on-device и не выгружаются (privacy NFR).

## Тестирование

EditMode-тесты на синтетических потоках кадров (по образцу `PoseTestFrames` /
`PushUpAnalyzerTests`):

- приседания: чистый повтор; недосед не увеличивает счёт; дрожание сигнала на пороге
  не даёт фантомных повторов;
- wall-sit: накопление секунд; пауза при `NotVisible`; грейс-период не рвёт удержание;
- yoko-geri: медленный подъём засчитан, быстрый мах — no-rep; удержание копится;
- mae geri: удар в каждую из трёх зон; «просили chudan, ударил gedan» → no-rep;
  «просили gedan, ударил jodan» → зачёт; отсутствие чамбера помечается;
- `RepCounter` после переименования: существующие тесты пуш-апа проходят без правок
  логики;
- `StatCalculator`: известные результаты → ожидаемые статы; нули; значения выше якорей
  обрезаются до 100.

**On-device smoke:** сборка APK песочницы (существующий `AndroidBuilder`), живое
выполнение каждой техники, счёт против ручного подсчёта, корректность cue и ракурсных
подсказок. При расхождениях — запись CSV и разбор в `PoseReviewer`, калибровка порогов.

## Порядок реализации (крупно)

1. Переименование `PushUpRepCounter` → `RepCounter` + зелёные существующие тесты.
2. `HoldTimer`, `KickHeightZone` + тесты.
3. Анализаторы: приседания → wall-sit → mae geri → yoko-geri (от простого к сложному),
   каждый с тестами и записью в каталог.
4. `Level0Results` + `StatCalculator` + тесты; строка статов в песочнице.
5. APK, on-device smoke, калибровка порогов по записям.
